# eco-app features

Living inventory of what ships from this monorepo. Component-level detail lives in the per-component docs linked below, which were carried over from the four source repos during the consolidation ([coilysiren/inbox#101](https://forgejo.coilysiren.me/coilysiren/inbox/issues/101)).

## The fused service

One image, one uvicorn process, entrypoint `eco_mcp_app.http_app:app` on port 4000.

- **MCP server** - `src/eco_mcp_app/`, the core. Stdio for Claude Desktop, Streamable-HTTP at `/mcp/` for URL-connected hosts. Each tool returns text + structured JSON, plus an `_meta.ui` Jinja card for MCP Apps hosts (the only HTML the server renders). The `/preview/*.json` endpoints expose those tool payloads as the SPA's data plane. The `initialize` response advertises the Eco game icon (a 48x48 PNG data URI) as `serverInfo.icons`, so URL-connected hosts like claude.ai render the Eco globe on the connector tile instead of a generic placeholder. Full tool/resource inventory: [docs/mcp/FEATURES.md](mcp/FEATURES.md).
- **Privileged /admin MCP** (experimental, feature-flagged off) - `src/eco_mcp_app/admin/`, a second inside-out MCP distinct from the public server above. Where the public MCP reads a live server's HTTP `/info`, this one reads a **local checkout** of the server's `Storage/` + `Configs/` tree. Mounted at `/admin` only when `ECO_ADMIN_ENABLED` is set, so the public `eco-mcp.coilysiren.me` deploy never exposes it. Three tools - `eco_save_status` (Game.eco/Game.db size + age), `eco_backup_list` (backup count, median cadence, newest/oldest), `eco_config_get` (a named `.eco`/`.diff.json` chosen from a fixed enum, never a filesystem path). Every result is redacted at one of three levels via a `level` arg: `public` (names hashed, secrets stripped), `operator` (default - names shown, secrets stripped), `raw` (also discloses secrets, **default DENY** - refused unless `ECO_ADMIN_ALLOW_RAW` is also set). Phase 1 of the Eco MCP battery ([#42](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/42), [#59](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/59)): read-only, local-files-only, no live-server touch, no deploy. The claude.ai OAuth gate and the node-local hostPath deploy are later #42 phases, ingress/deploy-side.
- **React frontend** - `frontend/`, a Vite + React + TypeScript SPA (no SSR). The Docker image builds it in a node stage and the fused service serves it at `/` (assets under `/assets`); a checkout without a build serves the JSON/MCP APIs only and returns a build hint for HTML routes (there is no server-rendered HTML surface - the old `/preview` card pages were removed, product UX is the SPA). The site is one flat surface ([#2](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/2)): the homepage is a thin directory of subpages (Server, Jobs, Progression, Economy, Trade, Trades, Crafting, Civics, Social, World, Climate, Ecoregion, Calculator, Replay, Community) with small live badges. `/replay` (the Kaihronicler - a read-only timeline of every recorded player action from the replay mod, consuming `/replay/api/v1/*`, with a `?q=` deep-link filter and filter-on-click - folds the former standalone replay browser into the one site per [#38](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/38)). `/economy` (KPI grid + health narrative), `/trade` (the trade & store logistics product surface - see its own bullet below), `/trades` (row-level trades ledger - who sold what to whom for how much, per-item price-over-time chart, top buyers/sellers, `?q=` deep links, filter-on-click), `/crafting` (ranked items/stations + top crafters by citizen, `?q=` deep links, filter-on-click), `/civics` (elections + outcomes, voter turnout with a two-series over-time chart, demographic trend, and new settlements - see its own bullet below), `/progression` (skill-history trajectories, per-day progression-trend small-multiples, most-gained-specialty / busiest-leveler leaderboards, expandable per-citizen timelines - see its own bullet below), `/social` (the social & chat surface - see its own bullet below), `/world` (world/industry mutation timeline - a per-day stacked-by-category chart of construction, roads, moved objects, explosions, garbage, and pollution, plus top world-shapers, top polluters, most-touched objects, and activity hotspots, cross-linked to `/climate` and `/crafting`), `/climate` (atmosphere KPIs, CO2 source/sink breakdown, CO2-effects mechanic driven by the live per-server climate ruleset read from the telemetry mod's `/api/v1/climate-settings` endpoint - falling back to documented Eco defaults when that endpoint is absent - and a plain-language pollution-machine-style explainer that spells out CO2, ground pollution, and sea-level consequences), and `/ecoregion` (biome-composition donut over raw world-area percents with an explicit unclassified/mixed-terrain slice, the top-3 closest real-world WWF ecoregions by cosine similarity against the normalized biome vector, and a biodiversity-drift boom/bust strip of the biggest per-species population movers since cycle start - a from-zero grower renders "new", and the strip degrades to a minimal-drift or admin-unavailable placeholder; consumes `/preview/get_eco_ecoregion.json`, [#20](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/20)) cross-link each other and consume the `/preview/*.json` data endpoints, and `/server` carries the live world snapshot from `/preview.json` (meteor countdown, players, world stats, 60s poll, graceful degraded state). A catch-all in `http_app.py` serves the SPA shell for client routes so hard refreshes survive. Scaffolding: react-router, eslint + vitest with component tests, run in CI. Dev verbs: `frontend-install` / `frontend-dev` / `frontend-build` / `frontend-test` / `frontend-lint`.
- **Jobs API** - `src/eco_spec_tracker/`, mounted at `/jobs/api` (public paths `/jobs/api/v1/*` plus `/v1/meta` for the mock-data flag). The jobs UI is the SPA's `/jobs` route consuming this API - now enriched with a **skill-history lane** ([#64](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/64)): each player card gains a best-effort "how they got here" timeline joined by name from `/preview/progression.json` (see the Progression bullet below), degrading to the plain current-state tables when that surface is unavailable. Detail: [docs/jobs/FEATURES.md](jobs/FEATURES.md).
- **Calculator** - the SPA's `/calculator` route (`frontend/src/pages/Calculator.tsx`), the eco-app home for **Eco Gnome** (MIT), a price calculator that derives optimal buy/sell prices from a player's professions and recipes. Today it links out to the Eco-Gnome team's public instance with the MIT attribution preserved. The plan ([#40](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/40)) is to self-host the MIT tool on `eco-app.coilysiren.me` and feed it Sirens' modded recipes/skills/items via the DataExporter mod, so the pricing is server-accurate rather than vanilla. Because upstream is a Blazor Server + Postgres service (not WASM), the self-host is a deploy-repo slot, not a static bake into the fused image. Design of record: [docs/calculator.md](calculator.md).
- **Sentry telemetry** - one shared idempotent init (`eco_mcp_app/telemetry.py`), DSN via the `SENTRY_DSN` env var from the deploy repo's ExternalSecret.
- **Dev target resolver** - `scripts/resolve-eco-target.sh`, run by the `http` verb to pick the eco game server base URL: LAN mDNS path first (the home router blackholes same-LAN tailnet WireGuard, [infrastructure#294](https://forgejo.coilysiren.me/coilyco-flight-deck/infrastructure/issues/294)), then the SSM-resolved tailnet FQDN, then the public host. An explicit `ECO_INFO_URL` wins outright; `ECO_ADMIN_BASE_URL` / `ECO_MAP_BASE_URL` / `UPSTREAM_URL` (jobs skills endpoint) default to the same base, and `UPSTREAM_API_KEY` is SSM-resolved so local `/jobs` shows real player data, not the mock fallback.

## Local-only components

- **Replay JSON API** - `src/eco_replay/`, the "Kaihronicler" (a Chronicler mirror): a FastAPI JSON API over the replay mod's SQLite event log (or the mod's HTTP endpoint, or a mock fallback). Mounted at `/replay/api` inside the fused service (public paths `/replay/api/v1/*` plus `/v1/meta` for the mock-data flag), consumed by the SPA's `/replay` route. The old Jinja/HTMX HTML surface was removed per the SPA-only rule ([#38](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/38), DLT epic [#37](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/37)). Detail: [docs/replay/README.md](replay/README.md).

## In-game C# plugins (`mods/`)

Server plugins for the Eco game server. Built with the `build-mod-*` ward verbs (or `build-mods` to compile all four at once), shipped to the server out of band. CI compiles every mod on push so a C# typo cannot reach the live server unseen ([#60](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/60)).

- **mods/jobs** - skills API plugin (`/api/v1/skills` for the jobs tracker, `/api/v1/citizens` for the crafting atlas's id→name join) plus a C# shell harness mirroring the API shape for local dev.
- **mods/replay** - player-action recorder writing the SQLite event log the replay browser reads. Action bodies are serialized with a structurally-bounded snapshot (allow-listed scalar props, wide references collapsed to `<name>`/`<n items>` summaries, 16 KB hard cap) and SQLite writes run on a background bounded-channel batched writer, never the game thread. Serializer unit tests: `ward exec test-mod-replay`.
- **mods/telemetry** - logs, exception capture, Eco game + runtime metrics, and OTLP traces (plugin-init spans plus a slow-handler detector) inside the game server. Detail: [mods/telemetry/docs/FEATURES.md](../mods/telemetry/docs/FEATURES.md).
- **mods/stores** - the live stores/economy exporter, two in-process HTTP routes. **`/api/v1/stores`** walks every live `StoreComponent` and emits each shelf's current offers (item, buy/sell, price, stock, currency, owner, location) so the store-directory, logistics-engine, and watcher siblings move from history-derived to shelf-accurate `Trades <item>` parity ([#55](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/55)). **`/api/v1/currency-holdings`** reads per-account, per-currency balances live from the in-process `CurrencyManager` and joins account owners to citizen names via `UserManager`, serving the DiscordLink `Currency <name>` top-holders list that trade history cannot reconstruct ([#58](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/58)). Both are reflection-based, null-tolerant walks (survive orphaned objects and removed items; the currency scanner takes no compile-time dependency on the economy types, so API drift degrades it to empty rather than breaking the compile gate) sharing the primitives in `src/Reflect.cs`, plus a C# shell harness mirroring both API shapes for local dev. DTO contracts: [mods/stores/docs/dto.md](../mods/stores/docs/dto.md) (stores), [mods/stores/docs/currency-holdings.md](../mods/stores/docs/currency-holdings.md) (currency holdings).

## Build and release

- **CI** - `.forgejo/workflows/build-publish.yml`: the Python validation job runs **inside the pinned aos dev-base image** (`forgejo.coilysiren.me/coilyco-flight-deck/agentic-os:<tag>`) through `ward exec test` / `ward exec lint` / `ward exec smoke`, so CI's gate is the same image and same verbs a headless `warded` agent runs - CI is red exactly when an agent could not land the change (parity). The tag is pinned, never `:latest`, so a dev-base bump is a deliberate PR that re-validates eco-app rather than a silent drift. This closed the divergence where CI stayed green while three dispatched runs died on the smoke gate in dev-base ([#56](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/56), [#57](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/57), aos CI-parity umbrella [agentic-os#328](https://forgejo.coilysiren.me/coilyco-flight-deck/agentic-os/issues/328)). Alongside it: a frontend lint/test/build job, and a **mods** job that compiles all four C# mods via `ward exec build-mods` **inside the same pinned dev-base image** (which ships the .NET 10 SDK + ICU, [agentic-os#329](https://forgejo.coilysiren.me/coilyco-flight-deck/agentic-os/issues/329)), so a compile error fails that standalone gate before the mods are shipped out of band ([#60](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/60)). That job also runs the replay mod's C# unit tests via `ward exec test-mod-replay`, so a BodySerializer behavioural regression is now a gated signal rather than one that compiles clean and fails silently outside CI ([#67](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/67)). The mods' `dotnet restore` (compile and test alike) is the one step reaching an external feed (api.nuget.org), so the job raises NuGet's HTTP retry and re-runs each up to three times to ride out the in-cluster runner's known-flaky external egress ([#69](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/69)). The **publish** job builds and pushes `coilysiren-eco-app` to the in-cluster registry and needs only `test` + `frontend`, **never `mods`**: the app image is SPA + MCP + jobs and carries no C# mods, so mod compilation cannot gate it - the mis-wired coupling that froze prod from #60 until [#68](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/68) decoupled it and moved the mods gate into dev-base. No deploy stage by design.
- **Deploy surface** - lives in `coilyco-bridge/deploy/services/eco-app` (manifests + rollout), per the layer invariant.

## Data surfaces

- **Dataset survey + probe how-to** - [docs/datasets/](datasets/README.md): every populated dataset on the live server (192/205, cycle-13 capture) split per theme, plus the full fresh-session recipe for probing series (`/datasets/get`), action CSVs (`/api/v1/exporter/actions`), auth, time semantics, and known traps. Umbrella tracker: [#7](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/7).
- **Crafting activity atlas** - [docs/crafting.md](crafting.md): the `get_eco_crafting_atlas` tool and `/crafting` page reconstruct a live production picture from the `ItemCraftedAction` / `HarvestOrHunt` / `ChopTree` / `DigOrMine` action CSVs (observed events, never recipe definitions - which aren't exposed over HTTP). Renders top items produced, crafting-station utilization, a per-citizen crafter leaderboard, and a station→item "flows into what" sankey (a static server-side SVG rather than runtime d3, so CSP needs no external JS). Stream-parses the unbounded late-cycle CSVs in a single pass with a per-action row valve, caches per (server, api-key) in `~/.cache/eco-mcp-app/crafting.sqlite` (5-min TTL), and owns the defensive-parse (`_corrected_index`) and id→name-join (`fetch_citizen_name_map`) machinery the trades ledger reuses ([#17](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/17), id→name link [#5](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/5)).
- **Trades ledger** - [docs/trades.md](trades.md): the `get_eco_trades` tool and `/trades` page reconstruct a row-level trades surface from the `CurrencyTrade` / `BarterTrade` action CSVs - every individual trade with parties, item, quantity, currency amount, and in-game day, plus the aggregates that fall out (top buyers/sellers, per-currency volume, most-traded items, per-item price-over-time). Shares the crafting atlas's defensive-parse and id→name-join machinery ([#6](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/6)).
- **Market price intelligence** - the `get_eco_market` tool and `/preview/market.json` plane fold the trades ledger into a per-item, per-currency price series: median / min / max / units-traded per in-game day, plus a short-vs-long-window trend verdict (rising / falling / flat, or "insufficient" when data is too thin). Consumes the [#6](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/6) row model rather than re-parsing. The in-game median also wires back into the `fair_price` advisor, which now cross-references it against the real-world FRED benchmark ("in-game median X vs real-world trend Y → looks over/under/fair"), degrading to the FRED-only narrative when an item has no in-game trades. Exceeds DiscordLink's single asking price with history, volume, and a real-world anchor ([#49](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/49)).
- **Store & trader directory** - the `get_eco_stores` tool and `/preview/stores.json` data plane fold the same trade history into two directories: **store profiles** keyed by shop owner + location (items traded, buy-vs-sell mix, price points, volume, unique counterparties, last-trade recency) and **trader profiles** per citizen (buys, sells, top items, volume, stores operated). Meets DiscordLink's `Trades <player>` / `Trades <store>` from history and **exceeds** it by surfacing the **store owner** it omits, plus per-store/per-trader volume and recency. The buy/sell split is read structurally off the party columns, not the undecoded `BoughtOrSold` enum, and owner/party ids resolve to names via the citizens surface (`Citizen #<id>` fallback). History-only - the live shelf snapshot is the reset-gated **mods/stores** exporter above ([#50](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/50), under the DiscordLink-replacement epic [#37](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/37)).
- **Trade & store logistics engine** - the `find_eco_trade` tool and `/preview/logistics.json` plane turn the trade ledger and live store shelves into buy/sell/haul decisions across four boards: **cheapest source** (rank stores selling an item by effective price - "where is iron ingot cheapest"), **best resale** (rank stores buying it, for a player holding stock), **arbitrage spreads** (items a store sells below another store buys, past twin percent + absolute thresholds, ranked by spread × movable volume), and **supply gaps** (items with buy-order demand but thin or absent supply, or priced well above their in-game median - what a new store should stock). Each price is marked **live** (the reset-gated **mods/stores** `/api/v1/stores` shelf, consumed best-effort) or **history-derived** (a recent-median reconstruction from the [#6](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/6) ledger that works today and is overwritten per shelf-line when the live offer exists). Empty and single-store markets report "not enough market depth" rather than a fabricated spread. **No DiscordLink equivalent** - it only ever lists trades, never reasons over them ([#51](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/51), epic [#37](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/37)).
- **Trade & store logistics surface** - the SPA's `/trade` route (`frontend/src/pages/Trade.tsx`), the **product surface** that fuses the whole trade push into one always-on web page under the DiscordLink-replacement epic ([#54](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/54)). One page carries a **currency strip** (money-supply summary from `/preview/currency.json`), a **market overview** (rising/falling movers and most-traded by volume from `/preview/market.json`), an **item drill-down** (median/latest/volume tiles plus a per-item price-history sparkline, `?q=<item>` deep-linked and cross-linked to `/trades` and `/crafting`), a **store & trader directory** (ranked by volume from `/preview/stores.json`), a **logistics board** (arbitrage spreads, cheapest-source, and supply gaps from `/preview/logistics.json` - the headline "what should I do" panel), and a read-only **watchers panel** (`/preview/watchers.json`). Every plane is fetched best-effort and independent: a sibling that has not landed yet 404s to a hidden panel rather than crashing the page, so the surface scaffolds ahead of its data planes and fills in as they land. Follows the wave-0 SPA pattern (react-router page, live homepage badge, filter-on-click, graceful degrade, vitest component tests in CI). This is the surface that makes the set **exceed** DiscordLink: coherent, always-on web with history, charts, and logistics reasoning versus ephemeral DM embeds (epic [#37](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/37)).
- **Progression / skills history** - [docs/progression.md](progression.md): the `get_eco_progression` tool and `/progression` page reconstruct skill **trajectories** from the seven progression action exporters (`GainProfession`, `GainSpecialty`, `LoseSpecialty`, `SpecialtyLevelUp`, `CharacterLevelUp`, `CompleteClass`, `EnrollAction`) plus best-effort daily-series discovery. Where the jobs surface shows *current* skills, this shows **how** citizens got there: per-citizen event timelines (professions gained, specialties gained/lost, level-up cadence), server-wide per-day trend small-multiples, and most-gained-specialty / busiest-leveler / class-completion leaderboards. Shares the crafting atlas's streamed-CSV, defensive-realign, and id→name-join machinery ([#5](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/5)), so no new C# mod and no game reset - everything is already exported. The `/preview/progression.json` plane feeds the SPA page and the `/jobs` history lane. Degrades cleanly on a thin/early-cycle server (empty state) or a disabled exporter (per-action warning). Column-shape caveat: the exporter headers weren't capturable live, so the skill/level column *names* are best-effort candidates keyed defensively off the header ([#64](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/64), survey [#7](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/7)).
- **Social & chat surface** - the `get_eco_social` tool, `/preview/social.json` data plane, and SPA `/social` route reconstruct the social side of a server from four action CSVs already exported (no new mod, no reset): `ChatSent` (full chat log), `Play` + `FirstLogin` (activity / new arrivals), and `ReputationTransfer` (who reps whom). The surface carries an activity timeline (chat volume + first-logins per in-game day), chat volume by channel and by author, a directed **reputation graph** (inline-SVG node-link, who reps whom), and a redacted recent-chat feed. **Redaction is load-bearing and public by default**: chat is player-authored content, so player names become stable non-reversible `player-<hash>` handles and every known name inside a message body is scrubbed to that handle - a test proves no raw name or raw body reaches the public path, and `/preview/social.json` is redacted even when the operator has lifted the names gate. Names-in-the-clear is operator-gated default-deny (needs `ECO_SOCIAL_ALLOW_NAMES` set server-side **and** `reveal_names` on the MCP call), mirroring the /admin `raw` posture. Shares the crafting/trades defensive-parse + id→name-join spine ([#5](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/5), [#6](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/6)); the social action column shapes were modeled from candidate header names (the exporter is admin-gated and no key was mounted at build) and want confirming against a live capture ([#63](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/63), survey [#7](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/7)).
- **World & industry activity** - [docs/world.md](world.md): the `get_eco_world` tool, the `/preview/world.json` data plane, and the SPA's `/world` route reconstruct the physical story of what players do to the world from the action-log exporter - **construction** and deconstruction, **terraforming**, **roads** tamped, world **objects** placed and moved, **explosions**, **garbage**, and **air pollution**. Nine action types (`ConstructOrDeconstruct`, `PlaceOrPickUpObject`, `MoveWorldObject`, `TampRoad`, `DropOrPickupGarbage`, `ObjectExplosion`, `PolluteAir`, plus `DigOrMine` / `ChopTree` re-framed as terraforming rather than production) fold into seven categories: a per-in-game-day **mutation timeline** stacked by category, a **top-world-shapers** and **top-polluters** leaderboard (numeric ids joined to names via the citizens surface, `Citizen #<id>` fallback), the **most-touched objects**, and coarse-binned activity **hotspots** ("where the bulldozers are"). Reuses the crafting atlas's streamed-CSV plumbing wholesale (stream-parse, the [#5](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/5) column corrector, the id→name join, Time→day) so it needs **no new C# mod and no game restart**. The `/world` SPA route cross-links `/climate` (where the pollution goes) and `/crafting` (what the digging becomes) and carries a live homepage badge. The single largest unconsumed slice of the pull-everything survey ([#7](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/7)) - 20 exporters, no reset ([#62](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/62)).
- **Trade watchers** - [docs/watchers.md](watchers.md): host-agnostic replacement for DiscordLink's `WatchTradeFeed` / `WatchTradeDisplay` / `UnwatchTradeFeed` / `ListTradeWatchers`, with no Discord dependency. The `eco_trade_watchers` MCP tool (`action` create / list / remove / evaluate) watches an item, store, trader, or a price threshold (e.g. "iron ingot under 2.5") against the trades the server already exports, so no new mod or reset. Each evaluation returns both semantics - the **feed** (matching trades new since the watcher's last-seen mark) and the **display** (current matching state). Watchers persist in a SQLite store (`~/.cache/eco-mcp-app/watchers.sqlite`, mirroring the fair-price cache) and surface read-only on the `/trades` SPA route via `/preview/watchers.json` (peek mode - viewing never consumes a feed). **Exceeds** DiscordLink by delivering to the website + MCP instead of Discord DMs, and by the numeric price predicate ([#52](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/52), epic [#37](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/37)).
- **Civics & governance surface** - [docs/civics.md](civics.md): the `get_eco_civics` MCP tool, the `/preview/civics.json` data plane, and the SPA `/civics` route reconstruct the **history + trend** half of governance from data the server already exports - no restart, no new C# mod. Folds the civic action exporters (`Vote`, `DidntVote`, `StartElection`, `JoinOrLeaveElection`, `WonElection`, `LostElection`, `DemographicChange`, `ResidencyChanged`, `BecomeCitizen`, `LeaveCitizenship`, `SettlementFounded`, `PlaceNewSettlementFoundation`, `StartHomestead`) plus civics/people daily-count series into: elections started + their outcomes, **voter turnout** (Vote vs DidntVote with a participation rate and most-active-voter leaderboard, and turnout over time), **demographic trend** (citizens gained/lost, net, residency moves, recent arrivals/departures), and **settlements founded / homesteads started**. Reuses the trade wave's streamed CSV plumbing - `crafting._corrected_index` realignment, the `/api/v1/citizens` id→name join (`Citizen #<id>` fallback), and the `Time / 86400` in-game-day convention. The `/civics` page cross-links `/economy` and `/server` and carries a live homepage badge. Complements **get_eco_government** (the current-state title/law snapshot); laws-in-effect aren't derivable from the action stream, so the surface points at the government card for those rather than fabricating them. Directly serves the epic's "elections and votes, laws, demographics" display set on the website instead of Discord embeds, and **exceeds** it by adding turnout + demographic trend over time ([#61](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/61), survey [#7](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/7), epic [#37](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/37)).
- **Per-user dossier (hidden)** - `src/eco_mcp_app/users.py`, the `/preview/user.json` + `/preview/users.json` data planes, and the SPA's hidden `/users/<hex>` + `/users` routes give **one page per player, every field the exporters carry about that individual**. The page is at `/users/<hex>` where `<hex>` is the **base16 of the username** (the SPA decodes it and asks the backend by name); **hidden** (no nav link) but **not** password-protected. `_gather_user_sources` fans out concurrently to every per-user surface - jobs skills + lastSeen, trades as buyer/seller/owner, crafting output, civics (votes/office/demographics/settlements), currency holdings, progression trajectory, and world shaping/pollution - and `build_user_dossier` pivots them into one dossier; each panel degrades on its own, so a dead exporter never sinks the page. General rule: a list **pivoted by user lists every user, never a truncated top-N** - `/users` is the complete roster (a union over each surface's per-user lists), and the one source that capped its per-user list, world's `byCitizen`/`byPolluter` (was top-25), was de-capped in `world.finalize`. Where an upstream slice still caps (currency top-holders per currency, progression skill trajectories to the busiest citizens) the dossier records a warning rather than implying completeness; fully de-capping those two is a follow-up ([#80](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/80)).
