# eco-app features

Living inventory of what ships from this monorepo. Component-level detail lives in the per-component docs linked below, which were carried over from the four source repos during the consolidation ([coilysiren/inbox#101](https://forgejo.coilysiren.me/coilysiren/inbox/issues/101)).

## The fused service

One image, one uvicorn process, entrypoint `eco_mcp_app.http_app:app` on port 4000.

- **MCP server** - `src/eco_mcp_app/`, the core. Stdio for Claude Desktop, Streamable-HTTP at `/mcp/` for URL-connected hosts. Each tool returns text + structured JSON. The `_meta.ui` Jinja widget card is **scoped to the world/region view only** ([#87](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/87)): only the three tools behind the SPA's `/map` surface - `get_eco_world`, `get_eco_map`, and `get_eco_ecoregion` - emit an MCP-app visual widget; every other tool is "just data" (its markdown + JSON blocks, no widget resource). That widget is the only HTML the server renders. The `/preview/*.json` endpoints expose those tool payloads as the SPA's data plane. The `initialize` response advertises the Eco game icon (a 48x48 PNG data URI) as `serverInfo.icons`, so URL-connected hosts like claude.ai render the Eco globe on the connector tile instead of a generic placeholder. Full tool/resource inventory: [docs/mcp/FEATURES.md](mcp/FEATURES.md).
- **Privileged /admin MCP** (experimental, feature-flagged off) - `src/eco_mcp_app/admin/`, a second inside-out MCP distinct from the public server above. Where the public MCP reads a live server's HTTP `/info`, this one reads a **local checkout** of the server's `Storage/` + `Configs/` tree. Mounted at `/admin` only when `ECO_ADMIN_ENABLED` is set, so the public `eco-mcp.coilysiren.me` deploy never exposes it. Three tools - `eco_save_status` (Game.eco/Game.db size + age), `eco_backup_list` (backup count, median cadence, newest/oldest), `eco_config_get` (a named `.eco`/`.diff.json` chosen from a fixed enum, never a filesystem path). Every result is redacted at one of three levels via a `level` arg: `public` (names hashed, secrets stripped), `operator` (default - names shown, secrets stripped), `raw` (also discloses secrets, **default DENY** - refused unless `ECO_ADMIN_ALLOW_RAW` is also set). Phase 1 of the Eco MCP battery ([#42](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/42), [#59](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/59)): read-only, local-files-only, no live-server touch, no deploy. The claude.ai OAuth gate and the node-local hostPath deploy are later #42 phases, ingress/deploy-side.
- **React frontend** - `frontend/`, a Vite + React + TypeScript SPA (no SSR). The Docker image builds it in a node stage and the fused service serves it at `/` (assets under `/assets`); a checkout without a build serves the JSON/MCP APIs only and returns a build hint for HTML routes (there is no server-rendered HTML surface - the old `/preview` card pages were removed, product UX is the SPA). The site is one flat surface ([#2](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/2)): the homepage is a thin directory of subpages (Info, Jobs, Trade, Items, Use cases, Crafting, Civics, World, Community) with small live badges, plus a card that links out to the Eco Gnome crafting calculator. The IA cleanup in [#90](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/90) collapsed the page set: the eco-gnome calculator dropped from a `/calculator` route to that homepage card, `/economy` was removed outright (superseding the down-render floated in [#87](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/87)), the standalone `/progression` page folded into `/jobs` as its trajectory layer, `/server` was renamed `/info`, the `/trades` ledger folded into `/trade`, and `/climate` folded into the World map (`/map`) as an environmental overlay; every retired path redirects to its new home so nothing 404s. **`/replay` and `/social` are URL-only** ([#73](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/73)): dropped from the nav and the homepage directory, and wrapped in a soft **page-password gate** (`components/PagePassword.tsx`) - the SPA asks `GET /page-auth` whether a password is configured, prompts if so, and verifies the answer server-side via `POST /page-auth` so the password never ships to the client. The password is a throwaway string from `ECO_PAGE_PASSWORD` (env, or SSM `/coilyco/eco-app/page-password` via `page_auth.py`); when none is set the gate stays open, so a bare local checkout is never locked out. It is a speed bump, not a security boundary - the JSON APIs behind those pages stay public. A shared **`<Loading>`** component (`components/Loading.tsx`, a CSS-only spinner + label) backs the heavier pages' fetch state. `/replay` (the Kaihronicler - a read-only timeline of every recorded player action from the replay mod, consuming `/replay/api/v1/*`, with a `?q=` deep-link filter and filter-on-click - folds the former standalone replay browser into the one site per [#38](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/38)). `/trade` (the trade & store logistics product surface, now also carrying the row-level trades ledger - who sold what to whom for how much, top buyers/sellers, `?q=` deep links, filter-on-click - that used to live at the standalone `/trades` page, which redirects here; see its own bullet below), `/crafting` (ranked items/stations + top crafters by citizen, `?q=` deep links, filter-on-click), `/items` + `/item` (the item directory - every item ever bought/sold/crafted, and a per-item pivot of every event that touches it - see its own bullet below), `/civics` (elections + outcomes, voter turnout with a two-series over-time chart, demographic trend, and new settlements - see its own bullet below), `/social` (the social & chat surface - see its own bullet below), `/map` (titled **World**, the merged world-map + ecoregion surface, [#82](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/82) - the live world preview blown up to a readable size with owner-coloured property-deed polygons and activity-hotspot rings overlaid on the actual map; a biome-and-water composition donut where salt water and fresh water are reclassified from the old undifferentiated ~61% grey slice down to ~20% genuine mountain/transitional terrain; hover a biome name to light up where it sits on the map via per-biome rasters; the top-3 closest real-world WWF ecoregions by cosine similarity; a biodiversity-drift boom/bust strip; and the world/industry mutation timeline stacked by category with top world-shapers, top polluters, most-touched objects - counted by touch events, not summed harvest quantity - and activity hotspots; and now the **atmosphere & climate overlay** folded in from the former `/climate` page ([#90](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/90)): the CO2 / temperature / sea-level read, the CO2 source/sink breakdown, and the plain-language pollution explainer, driven by the live per-server climate ruleset from the telemetry mod's `/api/v1/climate-settings` endpoint (falling back to documented Eco defaults when absent), laid over the biomes it acts on rather than as a separate page; cross-linked to `/crafting` and `/jobs`, consuming `/preview/get_eco_ecoregion.json`, `/preview/world.json`, `/preview-map.json`, and `/preview/get_eco_climate.json`; `/world`, `/ecoregion`, and `/climate` redirect here). The pages consume the `/preview/*.json` data endpoints, and `/info` (renamed from `/server`, which redirects here) carries the live world snapshot from `/preview.json` (meteor countdown, players, world stats, 60s poll, graceful degraded state). A catch-all in `http_app.py` serves the SPA shell for client routes so hard refreshes survive. Scaffolding: react-router, eslint + vitest with component tests, run in CI. Dev verbs: `frontend-install` / `frontend-dev` / `frontend-build` / `frontend-test` / `frontend-lint`.
- **Jobs API** - `src/eco_spec_tracker/`, mounted at `/jobs/api` (public paths `/jobs/api/v1/*` plus `/v1/meta` for the mock-data flag). The jobs UI is the SPA's `/jobs` route consuming this API - the **combined "who does what, and how they got there" surface**. It began as a current-state roster enriched with a per-player **skill-history lane** ([#64](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/64) - each player card gains a best-effort "how they got here" timeline joined by name from `/preview/progression.json`), and [#90](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/90) folded the whole standalone `/progression` page in as the page's trajectory layer: a "How the world got here" block carrying the server-wide per-day progression-trend small-multiples and the most-gained-specialty / busiest-leveler / class-completion leaderboards. [#103](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/103) adds the recipe-driven **"Most valuable to craft"** board on the same page, grouped by profession and ranked by true margin × supply-gap demand with a liquidity floor and the same glyph+label+color severity treatment as logistics. [#94](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/94) reordered the history block **above** the professions/specialties/players roster so the history reads first, cut the page to a single one-line intro and one heading tier, and dropped the universal starter skills **Survivalist** and **Self Improvement** (everyone has them, so they carry no signal) from every surface - professions, specialties, per-player rows, and the progression rank lists - via one `isUniversalSkill` filter in `Jobs.tsx` that normalizes both display names and raw Eco ids. The progression fetch stays best-effort, so a thin or unreachable surface degrades to the plain current-state tables. Detail: [docs/jobs/FEATURES.md](jobs/FEATURES.md).
- **Crafting calculator (Eco Gnome)** - a **homepage card** (`frontend/src/pages/Home.tsx`, `data-testid="dir-gnome"`) that links out to **Eco Gnome** (MIT), a price calculator that derives optimal buy/sell prices from a player's professions and recipes. It was a dedicated `/calculator` SPA page until the [#90](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/90) IA cleanup demoted it to this compact entry point (the old route redirects to `/`). Today the card opens the Eco-Gnome team's public instance with the MIT attribution preserved. The plan ([#40](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/40)) is to self-host the MIT tool on `eco-gnome.coilysiren.me` and feed it Sirens' modded recipes/skills/items via the DataExporter mod, so the pricing is server-accurate rather than vanilla. Because upstream is a Blazor Server + Postgres service (not WASM), the self-host is a deploy-repo slot, not a static bake into the fused image. Design of record: [docs/calculator.md](calculator.md).
- **Sentry telemetry** - one shared idempotent init (`eco_mcp_app/telemetry.py`), DSN via the `SENTRY_DSN` env var from the deploy repo's ExternalSecret.
- **Dev target resolver** - `scripts/resolve-eco-target.sh`, run by the `http` verb to pick the eco game server base URL: LAN mDNS path first (the home router blackholes same-LAN tailnet WireGuard, [infrastructure#294](https://forgejo.coilysiren.me/coilyco-flight-deck/infrastructure/issues/294)), then the SSM-resolved tailnet FQDN, then the public host. An explicit `ECO_INFO_URL` wins outright; `ECO_ADMIN_BASE_URL` / `ECO_MAP_BASE_URL` / `UPSTREAM_URL` (jobs skills endpoint) default to the same base, and `UPSTREAM_API_KEY` is SSM-resolved so local `/jobs` shows real player data, not the mock fallback.

## In-game C# plugins (`mods/`)

Server plugins for the Eco game server. Built with the `build-mod-*` ward verbs (or `build-mods` to compile all four at once), shipped to the server out of band. CI compiles every mod on push so a C# typo cannot reach the live server unseen ([#60](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/60)).

- **mods/jobs** - skills API plugin (`/api/v1/skills` for the jobs tracker, `/api/v1/citizens` for the crafting atlas's id→name join) plus a C# shell harness mirroring the API shape for local dev.
- **mods/replay** - player-action recorder writing the SQLite event log the replay browser reads. Action bodies are serialized with a structurally-bounded snapshot (allow-listed scalar props, wide references collapsed to `<name>`/`<n items>` summaries, 16 KB hard cap) and SQLite writes run on a background bounded-channel batched writer, never the game thread. Serializer unit tests: `ward exec test-mod-replay`.
- **mods/telemetry** - logs, exception capture, Eco game + runtime metrics, and OTLP traces (plugin-init spans plus a slow-handler detector) inside the game server. Detail: [mods/telemetry/docs/FEATURES.md](../mods/telemetry/docs/FEATURES.md).
- **mods/stores** - the live stores/economy exporter, two in-process HTTP routes. **`/api/v1/stores`** walks every live `StoreComponent` and emits each shelf's current offers (item, buy/sell, price, stock, currency, owner, location) so the store-directory, logistics-engine, and watcher siblings move from history-derived to shelf-accurate `Trades <item>` parity ([#55](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/55)). **`/api/v1/currency-holdings`** reads per-account, per-currency balances live from the in-process `CurrencyManager` and joins account owners to citizen names via `UserManager`, serving the DiscordLink `Currency <name>` top-holders list that trade history cannot reconstruct ([#58](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/58)). Both are reflection-based, null-tolerant walks (survive orphaned objects and removed items; the currency scanner takes no compile-time dependency on the economy types, so API drift degrades it to empty rather than breaking the compile gate) sharing the primitives in `src/Reflect.cs`, plus a C# shell harness mirroring both API shapes for local dev. DTO contracts: [mods/stores/docs/dto.md](../mods/stores/docs/dto.md) (stores), [mods/stores/docs/currency-holdings.md](../mods/stores/docs/currency-holdings.md) (currency holdings).

## Build and release

- **CI** - `.forgejo/workflows/build-publish.yml`: the Python validation job runs **inside the pinned aos dev-base image** (`forgejo.coilysiren.me/coilyco-flight-deck/agentic-os:<tag>`) through `ward exec test` / `ward exec lint` / `ward exec smoke`, so CI's gate is the same image and same verbs a headless `warded` agent runs - CI is red exactly when an agent could not land the change (parity). The tag is pinned, never `:latest`, so a dev-base bump is a deliberate PR that re-validates eco-app rather than a silent drift. This closed the divergence where CI stayed green while three dispatched runs died on the smoke gate in dev-base ([#56](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/56), [#57](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/57), aos CI-parity umbrella [agentic-os#328](https://forgejo.coilysiren.me/coilyco-flight-deck/agentic-os/issues/328)). Alongside it: a frontend lint/test/build job, and a **mods** job that compiles all four C# mods via `ward exec build-mods` **inside the same pinned dev-base image** (which ships the .NET 10 SDK + ICU, [agentic-os#329](https://forgejo.coilysiren.me/coilyco-flight-deck/agentic-os/issues/329)), so a compile error fails that standalone gate before the mods are shipped out of band ([#60](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/60)). That job also runs the replay mod's C# unit tests via `ward exec test-mod-replay`, so a BodySerializer behavioural regression is now a gated signal rather than one that compiles clean and fails silently outside CI ([#67](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/67)). The mods' `dotnet restore` (compile and test alike) is the one step reaching an external feed (api.nuget.org), so the job raises NuGet's HTTP retry and re-runs each up to three times to ride out the in-cluster runner's known-flaky external egress ([#69](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/69)). The **publish** job builds and pushes `coilysiren-eco-app` to the in-cluster registry and needs only `test` + `frontend`, **never `mods`**: the app image is SPA + MCP + jobs and carries no C# mods, so mod compilation cannot gate it - the mis-wired coupling that froze prod from #60 until [#68](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/68) decoupled it and moved the mods gate into dev-base. No deploy stage by design.
- **Deploy surface** - lives in `coilyco-bridge/deploy/services/eco-app` (manifests + rollout), per the layer invariant.

## Data surfaces

- **Dataset survey + probe how-to** - [docs/datasets/](datasets/README.md): every populated dataset on the live server (192/205, cycle-13 capture) split per theme, plus the full fresh-session recipe for probing series (`/datasets/get`), action CSVs (`/api/v1/exporter/actions`), auth, time semantics, and known traps. Umbrella tracker: [#7](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/7).
- **Crafting activity atlas** - [docs/crafting.md](crafting.md): the `get_eco_crafting_atlas` tool and `/crafting` page reconstruct a live production picture from the `ItemCraftedAction` / `HarvestOrHunt` / `ChopTree` / `DigOrMine` action CSVs (observed events, never recipe definitions - which aren't exposed over HTTP). Renders two separate produced-items boards - crafted items by unit count (`ItemCraftedAction`) and gathered resources by event count (harvest/chop/dig, whose raw `Count` is biomass magnitude, not a unit count - [#70](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/70)) - plus crafting-station utilization, an event-ranked per-citizen producer leaderboard, and a station→item "flows into what" sankey (a static server-side SVG rather than runtime d3, so CSP needs no external JS). Stream-parses the unbounded late-cycle CSVs in a single pass with a per-action row valve, caches per (server, api-key) in `~/.cache/eco-mcp-app/crafting.sqlite` (5-min TTL), and owns the defensive-parse (`_corrected_index`) and id→name-join (`fetch_citizen_name_map`) machinery the trades ledger reuses ([#17](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/17), id→name link [#5](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/5)).
- **Recipe definitions (bill-of-materials)** - [docs/recipes.md](recipes.md): `src/eco_mcp_app/recipes.py` and the `/preview/recipes.json` data plane hydrate the **recipe/skill/item definitions** the crafting atlas above explicitly can't see (it counts observed craft *events*; this is ingredients-in / product-out). The keystone of the recipe/pricing roadmap ([#98](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/98) follow-up A, [#100](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/100)), unblocking the recipes page (B), cost engine (C), value-per-profession (D), and pricing page (E). Rather than build a bespoke Eco `RecipeManager` dumper, it **ingests Eco Gnome's own export** (MIT, [#40](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/40)): the vanilla recipe graph bundled by eco-gnome-website (`ecocraft/eco_gnome_data.json`) is vendored at `data/eco_gnome_data.json` (pinned `master@28113f2`, 2026-07-04, `en-US`-trimmed but schema-identical to the DataExporter mod's dump) - **1,453 recipes / 1,526 items / 43 skills / 142 tags**. `build_recipe_index` folds it into the [#98](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/98) DTO - `Recipe { product, ingredients[], byproducts[], station, skill{name,level}, laborCost, craftMinutes, tableTierRequired, variants }` keyed off baseline `BaseValue` quantities (per-player skill/talent modifiers left for the cost engine), with tag-vs-item ingredients flagged and same-`FamilyName` siblings wired as `variants` - plus a `RecipeIndex` carrying `byProduct` / `bySkill` / `byStation` lookup maps, skill and tag tables, and provenance. Vendored (not fetched live) for reproducible builds and no build-time networking, per the [#105](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/105) probe; `/preview/recipes.json` optionally narrows by `?product=` / `?skill=` / `?station=`. When the self-host + DataExporter path lands (ward#585 / eco-ops#30) the modded export drops in over this seed with no parser rework. The one field the export doesn't carry, `tableTierRequired`, stays `null` until C derives it.
- **Recipes browse page** - the SPA's `/recipes` + `/recipe` routes (`frontend/src/pages/Recipes.tsx`, `Recipe.tsx`) and the `frontend/src/lib/recipesApi.ts` typed client, the browse surface over the recipe-definitions plane above ([#101](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/101) follow-up B on [#98](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/98)). Modeled on `/items` -> `/item`: `/recipes` is the directory (one deep-linkable row per recipe carrying station, profession + level, ingredient summary, labor, and craft time), and `/recipe?id=<name>` is the URL-only detail (reached only from the directory). Because the recipe graph is **one static bundled payload** (no `?server=`, no per-id endpoint), both routes fetch `/preview/recipes.json` once and the detail resolves a single recipe client-side by `name`. Filters, all URL-driven and client-side: `?q=` (product **+ ingredient** name search, the default), `?skill=` (profession), `?station=`, and `?ingredient=` - the **reverse lookup**, "what can I make with X", the highest-value filter, reached by clicking any ingredient on a detail page. `?tier=` (table tier) stays hidden until the cost engine ([#98](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/98) C) fills `tableTierRequired`, which is `null` across the vanilla seed. The detail shows the bill-of-materials (ingredients + byproducts, quantity-prefixed, item entries deep-linking to their `/item` market history, tag entries to the reverse lookup), the station / required skill+level / labor / craft-time facts, **"other ways to make this"** (built off `byProduct`, a superset of same-family `variants`), and the market cross-link: a card to `/item?item=<product>` where the item pivot already aggregates market price (`market.py`), who's crafted it (`crafting.py` `by_crafted`), and where to buy or sell it (`logistics.py`). Earns its own primary-nav entry (peer to Items and Crafting) plus one homepage card; degrades to a clear empty state when the bundle is missing. vitest component tests per page cover the filters, the reverse lookup, and the empty/degraded/not-found branches.
- **Bottom-up cost roll-up engine** - [docs/cost.md](cost.md): `src/eco_mcp_app/cost.py` fuses the recipe bill-of-materials (A, above) with the market median (`market.py`) into a **cost to craft one unit**, so margin (`medianUnitPrice - rolledUpCost`) and "is this worth crafting" become answerable. Follow-up C on the [#98](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/98) roadmap ([#102](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/102)), the engine the value-per-profession page (D) and "how to price X" page (E) read. Given a recipe it recurses over the ingredient edges, resolving each ingredient by a **make-or-buy** decision - the cheaper of buying it at market median or crafting it from its own recipe - down to raw leaves; a leaf with no market price is surfaced as an **unpriced input** (`complete: false`, `null` `perUnitCost`, item id in `unpricedInputs`), never silently zeroed. **Labor** (Eco meters it in calories) and **time** (`craftMinutes`) roll up alongside and monetize at caller-supplied `caloriePrice` / `minutePrice` (both default 0 - eco-app has no server-agnostic feed for what a calorie or a minute costs, so the raw calorie/minute totals always ride the payload and only fold into the money figure when a rate is given, echoed back as `costParams`). Handles **variants** (an item with several recipes is costed by the cheapest), **tag/category inputs** (resolve to the cheapest tag member), and **cycles** (a craft path that recurses into an item already on the stack drops to market/unpriced, so the roll-up terminates). Pure and I/O-free (`rollup_recipe` / `annotate_payload` take a plain price dict, unit-tested with hand-written BOMs in `tests/mcp/test_cost.py` - multi-level tree, unpriced leaf, cycle, tag, variants). Exposed on `/preview/recipes.json?cost=1`: each recipe row gains a `cost` breakdown (`ingredientCost` + `laborCost` + `timeCost` → `perUnitCost`, plus per-ingredient lines with `source` market/craft/unpriced), pricing leaves off the live market via `market.fetch_price_map` (an uncapped `fetch_market` flattened to one median per item); `?server=` targets the market, `?caloriePrice=` / `?minutePrice=` set the rates, and an unreachable market degrades to all-unpriced with a `warnings` note rather than failing the page.
- **Trades ledger** - [docs/trades.md](trades.md): the `get_eco_trades` tool and the `/trade` page (the standalone `/trades` page was folded into `/trade` in the [#90](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/90) IA cleanup - `/trades` redirects there) reconstruct a row-level trades surface from the `CurrencyTrade` / `BarterTrade` action CSVs - every individual trade with parties, item, quantity, currency amount, and in-game day, plus the aggregates that fall out (top buyers/sellers, per-currency volume, most-traded items, per-item price-over-time). Shares the crafting atlas's defensive-parse and id→name-join machinery ([#6](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/6)).
- **Item directory + per-item pivot** - `src/eco_mcp_app/items.py`, the `/preview/items.json` + `/preview/item.json?item=<id>` data planes, and the SPA's `/items` + `/item` routes. `/items` is the directory of **every item ever bought, sold, or crafted** - the union of the trades ledger's and crafting atlas's per-item aggregates, one deep-linkable row per item carrying its trade count, currency volume, and crafted quantity, with a `?q=` name filter, **sort chips** (activity / trades / trade volume / crafted), and **untraded items hidden by default** (a `?untraded=show` toggle reveals the craft-only noise) so the directory reads as a shopping list, not a dump ([#92](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/92)). Clicking an item opens `/item?item=<id>`, an **actionable per-item page** ([#92](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/92), absorbing [#85](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/85)): a top-of-page **summary** answering "should I craft it, where do I buy it, who do I sell it to" (crafters ranked by quantity produced, open sell offers / stock, open buy orders - pulled off the same `logistics.py` history+live-shelf spine `/trade` uses), then a **single merged reverse-chrono feed** that interleaves crafts and trades and reads in **relative time against the world clock** (`/info`'s `TimeSinceStart`, falling back to newest-event-as-now) - "someone bought a Steam Truck 2 hours ago", "Reihtnog crafted 4 Mortar 30 minutes ago". Runs of **identical consecutive rows compress** to one counted row ("Rechim crafted 100 Hewn Log at Carpentry Table (100 crafts over 12 minutes)"), and the feed carries **free-text search, actor + event-type filters, and real pagination**, all deep-linkable (`?q=` `?actor=` `?type=` `?page=`). The index reuses the two cached aggregates so it's cheap; the pivot re-streams the production CSVs (the atlas only keeps aggregates) to recover per-event rows, filtered to the one item and memory-bounded, and folds the trade leg off the shared `trades.fetch_parsed_trades` spine - so no new C# mod and no game reset. Reuses the crafting/trades defensive-realign, id→name-join (`Citizen #<id>` fallback), and `Time / 86400` in-game-day machinery ([#81](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/81)). **StumpLatrine finding** ([#92](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/92)): `?item=StumpLatrineItem` showing "2 people who each made 30+" is **real, not a parse defect** - live data is two genuine bulk-craft rows (Count 40 + 32 at a Workbench), one row per bulk craft, so `craftCount` (events) and `craftQuantity` (units) diverge legibly rather than double-count.
- **Market price intelligence** - the `get_eco_market` tool and `/preview/market.json` plane fold the trades ledger into a per-item, per-currency price series: median / min / max / units-traded per in-game day, plus a short-vs-long-window trend verdict (rising / falling / flat, or "insufficient" when data is too thin). Consumes the [#6](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/6) row model rather than re-parsing. The in-game median also wires back into the `fair_price` advisor, which now cross-references it against the real-world FRED benchmark ("in-game median X vs real-world trend Y → looks over/under/fair"), degrading to the FRED-only narrative when an item has no in-game trades. Exceeds DiscordLink's single asking price with history, volume, and a real-world anchor ([#49](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/49)).
- **Store & trader directory** - the `get_eco_stores` tool and `/preview/stores.json` data plane fold the same trade history into two directories: **store profiles** keyed by shop owner + location (items traded, buy-vs-sell mix, price points, volume, unique counterparties, last-trade recency) and **trader profiles** per citizen (buys, sells, top items, volume, stores operated). Meets DiscordLink's `Trades <player>` / `Trades <store>` from history and **exceeds** it by surfacing the **store owner** it omits, plus per-store/per-trader volume and recency. The buy/sell split is read structurally off the party columns, not the undecoded `BoughtOrSold` enum, and owner/party ids resolve to names via the citizens surface (`Citizen #<id>` fallback). History-only - the live shelf snapshot is the reset-gated **mods/stores** exporter above ([#50](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/50), under the DiscordLink-replacement epic [#37](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/37)).
- **Trade & store logistics engine** - the `find_eco_trade` tool and `/preview/logistics.json` plane turn the trade ledger and live store shelves into buy/sell/haul decisions across three boards: **best resale** (rank stores buying an item, for a player holding stock), **arbitrage spreads** (items a store sells below another store buys, past twin percent + absolute thresholds, ranked by spread × movable volume), and **supply gaps** (items with buy-order demand but thin or absent supply, or priced well above their in-game median - what a new store should stock, each folded with a **who-needs-it** per-citizen demand list that names the buyers and how much each still wants, [#77](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/77)), with the supply-gap board deliberately sized to surface 20+ gaps ([#95](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/95)). A per-item **cheapest source** is still computed and feeds the `/trade` drill-down "cheapest right now" pill, but the standalone cheapest-source board was dropped as noise ([#95](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/95)). Each price is marked **live** (the reset-gated **mods/stores** `/api/v1/stores` shelf, consumed best-effort) or **history-derived** (a recent-median reconstruction from the [#6](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/6) ledger that works today and is overwritten per shelf-line when the live offer exists). Empty and single-store markets report "not enough market depth" rather than a fabricated spread. **No DiscordLink equivalent** - it only ever lists trades, never reasons over them ([#51](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/51), epic [#37](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/37)).
- **Trade & store logistics surface** - the SPA's `/trade` route (`frontend/src/pages/Trade.tsx`), the **product surface** that fuses the whole trade push into one always-on web page under the DiscordLink-replacement epic ([#54](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/54)). One page carries a **currency strip** (money-supply summary from `/preview/currency.json`), a **market overview** (rising/falling movers and most-traded by volume from `/preview/market.json`), an **item drill-down** (median/latest/volume tiles plus a per-item price-history sparkline, `?q=<item>` deep-linked, filtering the folded-in ledger to the same item), the **row-level trades ledger** with top buyers/sellers (folded in from the former `/trades` page in the [#90](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/90) IA cleanup, sharing the one `?q=` filter), a **store & trader directory** (ranked by volume from `/preview/stores.json`), a **logistics board** (arbitrage spreads and supply gaps from `/preview/logistics.json` - the headline "what should I do" panel, whose client contract was realigned to the real `LogisticsReport` payload and whose supply gaps now render as spaced cards naming who needs each item and surface 20+ entries rather than clipping to ~8, [#77](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/77), [#95](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/95)), and a read-only **watchers panel** (`/preview/watchers.json`). Every plane is fetched best-effort and independent: a sibling that has not landed yet 404s to a hidden panel rather than crashing the page, so the surface scaffolds ahead of its data planes and fills in as they land. Follows the wave-0 SPA pattern (react-router page, live homepage badge, filter-on-click, graceful degrade, vitest component tests in CI). This is the surface that makes the set **exceed** DiscordLink: coherent, always-on web with history, charts, and logistics reasoning versus ephemeral DM embeds (epic [#37](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/37)).
- **Progression / skills history** - [docs/progression.md](progression.md): the `get_eco_progression` tool and the progression layer of `/jobs` reconstruct skill **trajectories** from the seven progression action exporters (`GainProfession`, `GainSpecialty`, `LoseSpecialty`, `SpecialtyLevelUp`, `CharacterLevelUp`, `CompleteClass`, `EnrollAction`) plus best-effort daily-series discovery. Where the jobs roster shows *current* skills, this shows **how** citizens got there: per-citizen event timelines (professions gained, specialties gained/lost, level-up cadence), server-wide per-day trend small-multiples, and most-gained-specialty / busiest-leveler / class-completion leaderboards. There is **no standalone `/progression` page** anymore - [#90](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/90) merged it into `/jobs` (per-player expandable timelines on each roster card, the server-wide trends + leaderboards as a "How the world got here" block below); the old route redirects to `/jobs`. Shares the crafting atlas's streamed-CSV, defensive-realign, and id→name-join machinery ([#5](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/5)), so no new C# mod and no game reset - everything is already exported. The `/preview/progression.json` plane feeds the merged `/jobs` surface. Degrades cleanly on a thin/early-cycle server (empty state) or a disabled exporter (per-action warning). Column-shape caveat: the exporter headers weren't capturable live, so the skill/level column *names* are best-effort candidates keyed defensively off the header ([#64](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/64), survey [#7](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/7)).
- **Social & chat surface** - the `get_eco_social` tool, `/preview/social.json` data plane, and SPA `/social` route reconstruct the social side of a server from four action CSVs already exported (no new mod, no reset): `ChatSent` (full chat log), `Play` + `FirstLogin` (activity / new arrivals), and `ReputationTransfer` (who reps whom). The surface carries an activity timeline (chat volume + first-logins per in-game day), chat volume by channel and by author, a directed **reputation graph** (inline-SVG node-link, who reps whom), and a redacted recent-chat feed that lists **every** message (no sample cap) with a relative-time column ("1 hour ago", measured against the newest event) rather than a raw in-game day. `#`-prefixed channels (system/noise) are filtered out of every count, chart, rank, and the feed, and the reputation fold **self-diagnoses**: if transfers parse but every edge loses its giver/receiver, a warning names the unrecognized party column so the empty graph explains itself against a live capture ([#74](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/74)). **Redaction is load-bearing and public by default**: chat is player-authored content, so player names become stable non-reversible `player-<hash>` handles and every known name inside a message body is scrubbed to that handle - a test proves no raw name or raw body reaches the public path, and `/preview/social.json` is redacted even when the operator has lifted the names gate. Names-in-the-clear is operator-gated default-deny (needs `ECO_SOCIAL_ALLOW_NAMES` set server-side **and** `reveal_names` on the MCP call), mirroring the /admin `raw` posture. Shares the crafting/trades defensive-parse + id→name-join spine ([#5](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/5), [#6](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/6)); the social action column shapes were modeled from candidate header names (the exporter is admin-gated and no key was mounted at build) and want confirming against a live capture ([#63](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/63), survey [#7](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/7)).
- **World & industry activity** - [docs/world.md](world.md): the `get_eco_world` tool, the `/preview/world.json` data plane, and the SPA's `/map` route (merged from the former `/world`, [#82](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/82)) reconstruct the physical story of what players do to the world from the action-log exporter - **construction** and deconstruction, **terraforming**, **roads** tamped, world **objects** placed and moved, **explosions**, **garbage**, and **air pollution**. Nine action types (`ConstructOrDeconstruct`, `PlaceOrPickUpObject`, `MoveWorldObject`, `TampRoad`, `DropOrPickupGarbage`, `ObjectExplosion`, `PolluteAir`, plus `DigOrMine` / `ChopTree` re-framed as terraforming rather than production) fold into seven categories: a per-in-game-day **mutation timeline** stacked by category, a **top-world-shapers** and **top-polluters** leaderboard (numeric ids joined to names via the citizens surface, `Citizen #<id>` fallback), the **most-touched objects** (counted by touch *events*, not summed harvest quantity - the [#70](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/70)-style unit-vs-biomass fix, [#82](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/82)), and coarse-binned activity **hotspots** ("where the bulldozers are", also ringed on the `/map` render). Reuses the crafting atlas's streamed-CSV plumbing wholesale (stream-parse, the [#5](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/5) column corrector, the id→name join, Time→day) so it needs **no new C# mod and no game restart**. The `/map` SPA route (titled **World**) now carries the climate/atmosphere content inline as an environmental overlay rather than cross-linking a separate `/climate` page ([#90](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/90)), cross-links `/crafting` (what the digging becomes) and `/jobs` (who is shaping the world), and carries a live homepage badge. The single largest unconsumed slice of the pull-everything survey ([#7](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/7)) - 20 exporters, no reset ([#62](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/62)).
- **Trade watchers** - [docs/watchers.md](watchers.md): host-agnostic replacement for DiscordLink's `WatchTradeFeed` / `WatchTradeDisplay` / `UnwatchTradeFeed` / `ListTradeWatchers`, with no Discord dependency. The `eco_trade_watchers` MCP tool (`action` create / list / remove / evaluate) watches an item, store, trader, or a price threshold (e.g. "iron ingot under 2.5") against the trades the server already exports, so no new mod or reset. Each evaluation returns both semantics - the **feed** (matching trades new since the watcher's last-seen mark) and the **display** (current matching state). Watchers persist in a SQLite store (`~/.cache/eco-mcp-app/watchers.sqlite`, mirroring the fair-price cache) and surface read-only on the `/trade` SPA route via `/preview/watchers.json` (peek mode - viewing never consumes a feed). **Exceeds** DiscordLink by delivering to the website + MCP instead of Discord DMs, and by the numeric price predicate ([#52](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/52), epic [#37](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/37)).
- **Civics & governance surface** - [docs/civics.md](civics.md): the `get_eco_civics` MCP tool, the `/preview/civics.json` data plane, and the SPA `/civics` route reconstruct the **history + trend** half of governance from data the server already exports - no restart, no new C# mod. Folds the civic action exporters (`Vote`, `DidntVote`, `StartElection`, `JoinOrLeaveElection`, `WonElection`, `LostElection`, `DemographicChange`, `ResidencyChanged`, `BecomeCitizen`, `LeaveCitizenship`, `SettlementFounded`, `PlaceNewSettlementFoundation`, `StartHomestead`) plus civics/people daily-count series into: elections started + their outcomes, **voter turnout** (Vote vs DidntVote with a participation rate and most-active-voter leaderboard, and turnout over time), **demographic trend** (citizens gained/lost, net, residency moves, recent arrivals/departures), and **settlements founded / homesteads started**. Reuses the trade wave's streamed CSV plumbing - `crafting._corrected_index` realignment, the `/api/v1/citizens` id→name join (`Citizen #<id>` fallback), and the `Time / 86400` in-game-day convention. The `/civics` page cross-links `/info` (renamed from `/server` in the [#90](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/90) IA cleanup) and carries a live homepage badge. Complements **get_eco_government** (the current-state title/law snapshot); laws-in-effect aren't derivable from the action stream, so the surface points at the government card for those rather than fabricating them. Directly serves the epic's "elections and votes, laws, demographics" display set on the website instead of Discord embeds, and **exceeds** it by adding turnout + demographic trend over time ([#61](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/61), survey [#7](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/7), epic [#37](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/37)).
- **Per-user dossier (hidden)** - `src/eco_mcp_app/users.py`, the `/preview/user.json` data plane, and the SPA's hidden `/users/<hex>` route give **one actionable page per player, every field the exporters carry about that individual**. The page is at `/users/<hex>` where `<hex>` is the **base16 of the username** (the SPA decodes it and asks the backend by name); **hidden** (no nav link) but **not** password-protected. `_gather_user_sources` fans out concurrently to every per-user surface - jobs skills + lastSeen, trades as buyer/seller/owner, crafting output, civics (votes/office/demographics/settlements), currency holdings, progression trajectory, and world shaping/pollution - and `build_user_dossier` pivots them into one dossier; each panel degrades on its own, so a dead exporter never sinks the page. The dossier **leads with an "At a glance" actionable summary** ([#93](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/93)) built from the same market spine `/trade` uses (`logistics.py` live shelf + supply gaps, `stores.py` per-trader footprint): what the player is **selling and buying right now** (owner-matched open offers, falling back to their recent sell/buy footprint when the live shelf is reset-gated), what they are **best positioned to make** (their highest specialties crossed against the market's current supply gaps), and **recent activity in relative time** ("3 hours ago", from the shared `formatRelativeTime`); the full per-surface panels follow unchanged. Every day-bearing row now renders through the shared `formatDayHour` day+hour clock (`Day 3, 12:00`) rather than a raw `Time / 86400` float. The one source that capped its per-user list, world's `byCitizen`/`byPolluter` (was top-25), was de-capped in `world.finalize` ([#80](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/80)); where an upstream slice still caps (currency top-holders per currency, progression skill trajectories to the busiest citizens) the dossier records a warning rather than implying completeness, a follow-up. The **all-users listing** (`/users` index + `/preview/users.json` + `build_roster`) was **removed** in [#93](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/93) (closes [#86](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/86)); the old `/users` path redirects to the homepage.
- **Use-case hub + demand-side pages** - [docs/uses.md](uses.md): the SPA's `/uses` hub (`frontend/src/pages/Uses.tsx`) plus four task-framed, demand-side use-case pages, the practical-usefulness slice from [#99](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/99) (follow-up F on the design in [#98](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/98)). The hub is the **only homepage card** the use-case family gets (`dir-uses`); the four pages are **URL-only**, reached from the hub, mirroring how `/item` is only reached from `/items`. Each page states a job and composes panels from data eco-app already hydrates - **no new data plane**, so it shipped ahead of the recipe-dependent use cases (follow-ups A-E on [#98](https://forgejo.coilysiren.me/coilyco-gaming/eco-app/issues/98), gated on the recipe exporter and listed muted as "coming soon" on the hub). **`/uses/demand`** ("what's in demand right now") ranks the logistics supply gaps by quantity wanted, each with a glyph+label+colour severity tag and a who-needs-it buyer list. **`/uses/buy-sell`** ("where to buy X cheapest / sell X highest") picks an item (`?item=<id>` deep link) and shows the cheapest sell shelves and best buy shelves, each naming store, owner, price, quantity, and live/history source. **`/uses/arbitrage`** ("buy low here, sell high there") renders the cross-store arbitrage spreads ranked by opportunity. **`/uses/shop-check`** ("is my shop priced right?") picks a store (`?store=<key>`) and joins its per-item `avgUnitPrice` against the market median, flagging items past ±15% over/under market - the one page that joins two planes, degrading to a clear note if either is unavailable. Every panel degrades on its own via `fetchJsonOrNull`, so one dead source never blanks a page; each page carries one heading tier and is deep-linkable for QA. Reuses `formatCount` / `prettifyEcoName` and the `/trade` logistics/stores/market clients wholesale, with vitest component tests per page including the degraded-when-null branch.
